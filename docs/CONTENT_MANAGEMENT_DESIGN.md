# 직접 관리할 수 있는 사이트 운영 설계

설계일: 2026-10-20. 현재 Jekyll + GitHub Pages 구조를 바탕으로 한다. 이 문서는 후속 편집 화면의 구현 명세이며, 편집 화면·인증 서버를 이미 만들었다는 의미는 아니다.

## 사용자가 할 수 있어야 하는 일

브라우저에서 프로필, 연구, 논문, 수상 항목을 수정하고 자료를 등록한다. 저장한 초안을 실제 페이지 형태로 확인한 뒤 공개한다. 어떤 항목이 어디에 표시되는지, 자료를 마지막으로 확인한 날과 미확인 사유를 볼 수 있어야 한다. 실수했을 때 이전 버전으로 복구할 수 있어야 한다.

## 권장 운영 방식

**1차 구현: 이 Mac에서 실행하는 개인 관리 화면 + 기존 GitHub Pages 공개 사이트.** 관리 도구가 로컬 파일을 읽고 저장하며, 미리보기와 공개할 변경 목록을 보여준다. GitHub 로그인은 기존 계정 인증을 사용하고 비밀 토큰을 공개 페이지에 넣지 않는다. 공개 사이트에는 로그인이나 편집 기능을 추가하지 않는다.

이 방식은 현재 무료 정적 사이트와 로컬 자료 흐름을 유지하면서 원본 파일, 내부 메모와 공개 파일을 함께 관리할 수 있다. 다른 컴퓨터나 휴대전화에서도 편집하려면 이후 별도 인증 방식이 필요하다. 그 요구가 생기면 비공개 관리 서버 또는 GitHub 연동 CMS를 선택한다. 현재는 계정·유료 서비스·조직을 새로 만들지 않는다.

## 관리 화면 구성

| 메뉴 | 화면에서 하는 일 | 저장 위치 |
| --- | --- | --- |
| 대시보드 | 공개 버전/초안 차이, 최근 배포 결과, 누락 자료, 미확인 링크 확인 | 로컬 작업 상태 + Git 기록 |
| 프로필 | 이름, 소속, 연구 관심, 소개글, 사진과 연락처 편집 | `_data/profile.json`, 소개 본문, 공개용 사진 |
| 연구 | 프로젝트 추가·수정·정렬, 관련 논문 연결 | `_data/profile.json`의 research |
| 논문 | 제목·저자·학회·날짜·종류, 짧은 본문, Paper/Poster/Code 링크 편집 | `_publications/*.md` |
| 수상·활동 | 항목 편집, 기사·증빙 선택, 연결될 페이지 확인 | profile + portfolio_links + award_publications |
| 자료함 | 원고·포스터·상장·CV 검색, 원본/공개본 구분, 연결 항목 및 파일 상태 확인 | 공개 파일 목록 + 비공개 로컬 자료 목록 |
| 출처·링크 | 기사와 기록 비교, 확인일/접속 상태/보류 사유 조회·수정 | `_data/portfolio_links.json`, 로컬 점검 보고서 |
| 미리보기·공개 | 데스크톱/모바일 미리보기, 공개할 변경 선택, 검사 결과와 배포 이력 확인 | Git 초안과 공개 브랜치 |

페이지 코드·JSON 필드 이름은 일반 편집 화면에서 드러내지 않는다. 사용자는 필드명으로 저장 위치를 추측할 필요 없이, 해당 항목이 표시되는 페이지 링크를 눌러 확인한다. 고급 메뉴에서만 원본 파일을 열 수 있게 한다.

## 항목을 수정하는 흐름

1. 목록에서 항목을 선택하면 편집 폼과 현재 공개된 화면 링크가 나온다.
2. 수정 후 **초안 저장**을 누른다. 필수값, 날짜 형식, 중복 ID, 연결할 자료의 존재 여부를 즉시 확인한다.
3. **미리보기**를 누르면 해당 초안을 읽는 별도 로컬 빌드가 열리고, 실제 공개 사이트의 동일한 템플릿을 사용한다.
4. **공개할 변경 확인**에서 바뀐 문구·항목·파일과 영향을 받는 페이지를 보여준다. 다른 미완성 초안은 포함하지 않는다.
5. 사용자가 **사이트에 반영**을 누르면 선택한 변경만 커밋한다. 원격 변경이 있으면 자동으로 덮어쓰지 않고 차이를 제시한다.
6. GitHub 배포 성공 여부를 표시한다. 실패하면 기존 공개 사이트가 유지되며, 실패 이유와 수정할 항목을 보여준다.
7. **이전 공개 버전으로 복구**는 되돌림 커밋을 만들어 같은 검사·배포 과정을 따른다. 기록을 지우는 강제 푸시는 사용하지 않는다.

## 자료함 설계

자료마다 다음을 저장한다.

- 자료 ID, 화면에 보일 이름, 종류(Paper/Poster/Award/CV/Image/Link)
- 연결할 항목 ID, 이 자료가 표시되는 페이지
- 파일 형식·크기·체크섬, 공개 파일의 주소
- 원본 위치, 공개본 생성 여부, 마지막 확인일과 메모
- 공개 상태: 비공개 원본 / 공개 준비 / 공개 허용 / 현재 공개
- 개인정보 제거 여부와 공개 허용 범위

**비공개 원본 위치와 메모는 `.local/library.json`에만 둔다.** 이 폴더는 Git 추적과 Jekyll 출력에서 제외한다. 공개 가능한 이름·URL·연결 정보만 공개 데이터에 저장한다. 기존 `_data/portfolio_links.json`은 공개 출처 기록이므로 사적인 메모나 다운로드 원본의 로컬 경로를 추가하지 않는다.

자료 등록 시 공개본을 별도로 선택하고, 원본을 자동으로 공개 폴더에 복사하지 않는다. 공개 전 어떤 파일이 누구나 다운로드 가능한 상태가 되는지 보여준다. 자료 교체 시 연결된 페이지를 나열하고 기존 주소를 유지할지 새 버전 주소로 바꿀지 고를 수 있어야 한다. 사용 중인 파일은 참조를 보여준 후에만 삭제한다.

원고, 그림, PDF 내용은 자동으로 생성하거나 사실을 추정해 채우지 않는다. 기존 공개 승인은 해당 자료에 대해 유지하고, 새 자료의 범위와 공개 여부를 확인한다.

## 데이터 구조와 이미 적용한 기반

- 프로필, 연구, 수상, 활동, 논문에 고정 ID를 부여했다. 제목이 바뀌어도 ID는 유지한다.
- 기사 연결은 `portfolio_links.entries[].item_id`, 수상-논문 연결은 `award_publications[].award_id`로 찾는다.
- 옛 `match` 필드는 당시 연결한 문구를 확인하는 참고 기록이다. 실제 연결 키가 아니다.
- 논문의 ID와 공개 주소(permalink)는 별도 값이다. 제목 수정 때문에 기존 공개 주소를 바꾸지 않는다.
- 화면은 데이터 파일에서 읽는다. 편집 폼도 같은 파일을 저장하고 별도 복제 데이터베이스를 만들지 않는다.
- 현재 프로필 원본과 설정 파일에 일부 이름 정보가 중복되어 있으므로, 관리 화면에서 프로필 이름을 바꿀 때 메타데이터와 설정의 표시 정보도 함께 갱신하도록 구현한다.
- 공개 정적 PDF CV는 HTML과 별도 산출물이다. 프로필 수정만으로 PDF를 새로 만들었다고 표시하지 않는다. 자료함에 웹 정보와 PDF의 마지막 반영일을 따로 보여준다.

## 로컬 관리 도구의 구현 경계

- 관리 서버는 `127.0.0.1`에만 열고 작업 디렉터리를 고정한다.
- 동일 출처 확인과 세션별 요청 토큰으로 다른 웹사이트가 로컬 관리 API를 호출하지 못하게 한다.
- 업로드는 허용된 형식과 크기만 받고 파일명·경로를 정리한다. 임의 경로 저장, 셸 명령 입력, 비공개 서버 접속 기능은 제공하지 않는다.
- 초안 수정 중인 파일을 다른 도구가 바꿨다면 저장 전에 충돌을 표시한다. 저장은 임시 파일과 원자적 교체를 사용한다.
- 실행할 명령은 검증·미리보기·커밋·배포 등 고정 작업으로 한정한다. 사용자 입력을 셸 명령에 이어 붙이지 않는다.
- 자료함의 개인 메모와 내부 파일은 공개 빌드에 들어갈 수 없도록 허용 목록으로 공개 파일을 선택한다.
- 테스트·백업·미리보기 파일은 `.local/`에 두고 공개 소스와 함께 게시하지 않는다.

## 구현 순서와 완료 조건

| 단계 | 구현 범위 | 완료 판단 |
| --- | --- | --- |
| 1 | 읽기 전용 대시보드·자료함·출처 목록 | 항목을 누르면 공개 페이지와 자료를 찾을 수 있고 누락 파일을 확인할 수 있음 |
| 2 | 프로필·연구·논문·수상 편집 폼, 초안 저장 | 제목을 바꿔도 연결이 유지되며 잘못된 입력은 원본을 변경하기 전에 안내 |
| 3 | 초안별 실제 페이지 미리보기·공개 변경 선택 | 공개하지 않은 초안과 개인 파일이 반영 대상에 섞이지 않음 |
| 4 | GitHub 공개·배포 상태·복구 | 공개 성공/실패를 확인하고 이전 버전으로 되돌릴 수 있음 |

현재 기술 개선 단계에서 데이터 ID, 검증, 자산 준비, 수동 링크 점검과 배포 검사까지 마련했다. 위 편집 폼과 로컬 관리 서버는 후속 구현 대상이다.
